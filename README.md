# Интернет-магазин «Web-Larёk»
«Web-Larёk» — это интернет-магазин с товарами для веб-разработчиков, где пользователи могут просматривать товары, добавлять их в корзину и оформлять заказы. Сайт предоставляет удобный интерфейс с модальными окнами для просмотра деталей товаров, управления корзиной и выбора способа оплаты, обеспечивая полный цикл покупки с отправкой заказов на сервер.

## Архитектура приложения

Код приложения разделен на слои согласно парадигме MVP (Model-View-Presenter), которая обеспечивает четкое разделение ответственности между классами слоев Model и View. Каждый слой несет свой смысл и ответственность:

Model - слой данных, отвечает за хранение и изменение данных.  
View - слой представления, отвечает за отображение данных на странице.  
Presenter - презентер содержит основную логику приложения и  отвечает за связь представления и данных.

Взаимодействие между классами обеспечивается использованием событийно-ориентированного подхода. Модели и Представления генерируют события при изменении данных или взаимодействии пользователя с приложением, а Презентер обрабатывает эти события используя методы как Моделей, так и Представлений.

### Базовый код

#### Класс Component
Является базовым классом для всех компонентов интерфейса.
Класс является дженериком и принимает в переменной `T` тип данных, которые могут быть переданы в метод `render` для отображения.

Конструктор:  
`constructor(container: HTMLElement)` - принимает ссылку на DOM элемент за отображение, которого он отвечает.

Поля класса:  
`container: HTMLElement` - поле для хранения корневого DOM элемента компонента.

Методы класса:  
`render(data?: Partial<T>): HTMLElement` - Главный метод класса. Он принимает данные, которые необходимо отобразить в интерфейсе, записывает эти данные в поля класса и возвращает ссылку на DOM-элемент. Предполагается, что в классах, которые будут наследоваться от `Component` будут реализованы сеттеры для полей с данными, которые будут вызываться в момент вызова `render` и записывать данные в необходимые DOM элементы.  
`setImage(element: HTMLImageElement, src: string, alt?: string): void` - утилитарный метод для модификации DOM-элементов `<img>`


#### Класс Api
Содержит в себе базовую логику отправки запросов.

Конструктор:  
`constructor(baseUrl: string, options: RequestInit = {})` - В конструктор передается базовый адрес сервера и опциональный объект с заголовками запросов.

Поля класса:  
`baseUrl: string` - базовый адрес сервера  
`options: RequestInit` - объект с заголовками, которые будут использованы для запросов.

Методы:  
`get(uri: string): Promise<object>` - выполняет GET запрос на переданный в параметрах ендпоинт и возвращает промис с объектом, которым ответил сервер  
`post(uri: string, data: object, method: ApiPostMethods = 'POST'): Promise<object>` - принимает объект с данными, которые будут переданы в JSON в теле запроса, и отправляет эти данные на ендпоинт переданный как параметр при вызове метода. По умолчанию выполняется `POST` запрос, но метод запроса может быть переопределен заданием третьего параметра при вызове.  
`handleResponse(response: Response): Promise<object>` - защищенный метод проверяющий ответ сервера на корректность и возвращающий объект с данными полученный от сервера или отклоненный промис, в случае некорректных данных.

#### Класс EventEmitter
Брокер событий реализует паттерн "Наблюдатель", позволяющий отправлять события и подписываться на события, происходящие в системе. Класс используется для связи слоя данных и представления.

Конструктор класса не принимает параметров.

Поля класса:  
`_events: Map<string | RegExp, Set<Function>>)` -  хранит коллекцию подписок на события. Ключи коллекции - названия событий или регулярное выражение, значения - коллекция функций обработчиков, которые будут вызваны при срабатывании события.

Методы класса:  
`on<T extends object>(event: EventName, callback: (data: T) => void): void` - подписка на событие, принимает название события и функцию обработчик.  
`emit<T extends object>(event: string, data?: T): void` - инициализация события. При вызове события в метод передается название события и объект с данными, который будет использован как аргумент для вызова обработчика.  
`trigger<T extends object>(event: string, context?: Partial<T>): (data: T) => void` - возвращает функцию, при вызове которой инициализируется требуемое в параметрах событие с передачей в него данных из второго параметра.

## Типы данных

Файл `src/types/index.ts` содержит интерфейсы и типы, используемые в приложении.

**IProduct** — интерфейс товара:  
`id: string` — уникальный идентификатор товара  
`description: string` — описание товара  
`image: string` — URL изображения товара  
`title: string` — название товара  
`category: string` — категория товара  
`price: number | null` — цена товара (может быть null, если цена не установлена)

**IBuyer** — интерфейс данных покупателя:  
`payment: TPayment | ''` — способ оплаты (может быть пустой строкой до выбора)  
`email: string` — email покупателя  
`phone: string` — телефон покупателя  
`address: string` — адрес доставки

**TPayment** — тип способа оплаты:  
`'card' | 'cash'` — оплата картой или наличными

**IProductListResponse** — интерфейс ответа сервера со списком товаров:  
`total: number` — общее количество товаров  
`items: IProduct[]` — массив товаров

**IOrder** — интерфейс данных заказа:  
`payment: TPayment | ''` — способ оплаты (пустая строка, если еще не выбран)  
`email: string` — email покупателя  
`phone: string` — телефон покупателя  
`address: string` — адрес доставки  
`total: number` — общая стоимость заказа  
`items: string[]` — массив идентификаторов товаров в заказе

**IOrderResult** — интерфейс результата оформления заказа:  
`id: string` — идентификатор оформленного заказа  
`total: number` — общая сумма заказа

**IValidationErrors** — тип для объекта ошибок валидации:  
`Partial<Record<keyof IBuyer, string>>` — объект, где ключи соответствуют полям IBuyer, а значения содержат текст ошибки

## Модели данных

### Класс Catalog

Отвечает за хранение и управление данными каталога товаров. Хранит массив всех доступных товаров и текущий выбранный товар для детального просмотра.

Конструктор:  
`constructor(events: IEvents)` — принимает экземпляр шины событий для генерации событий при изменении данных

Поля класса:  
`_items: IProduct[]` — массив всех товаров каталога  
`_selectedProduct: IProduct | null` — выбранный товар для детального отображения

Методы класса:  
`setItems(items: IProduct[]): void` — сохраняет массив товаров в модель  
`getItems(): IProduct[]` — возвращает массив всех товаров  
`getItemById(id: string): IProduct | undefined` — возвращает товар по его идентификатору  
`setSelected(product: IProduct | null): void` — сохраняет товар для детального отображения  
`getSelected(): IProduct | null` — возвращает выбранный товар

### Класс Cart

Отвечает за управление товарами в корзине покупок. Хранит массив товаров, добавленных пользователем.

Конструктор:  
`constructor(events: IEvents)` — принимает экземпляр шины событий для генерации событий при изменении корзины

Поля класса:  
`_items: IProduct[]` — массив товаров в корзине

Методы класса:  
`getItems(): IProduct[]` — возвращает массив товаров в корзине  
`addItem(item: IProduct): void` — добавляет товар в корзину, если он еще не добавлен  
`removeItem(id: string): void` — удаляет товар из корзины по идентификатору  
`clear(): void` — очищает корзину  
`getTotalPrice(): number` — возвращает общую стоимость всех товаров в корзине  
`getTotalCount(): number` — возвращает количество товаров в корзине  
`hasItem(id: string): boolean` — проверяет наличие товара в корзине по идентификатору

### Класс Order

Отвечает за хранение и валидацию данных покупателя при оформлении заказа. Поддерживает частичное обновление данных.

Конструктор:  
`constructor(events: IEvents)` — принимает экземпляр шины событий для генерации событий при изменении данных заказа

Поля класса:  
`_payment: TPayment | ''` — выбранный способ оплаты  
`_email: string` — email покупателя  
`_phone: string` — телефон покупателя  
`_address: string` — адрес доставки

Методы класса:  
`set(data: Partial<IBuyer>): void` — сохраняет данные покупателя, поддерживает частичное обновление без удаления существующих значений  
`getAll(): IBuyer` — возвращает все данные покупателя  
`clear(): void` — очищает все данные покупателя  
`validate(): IValidationErrors` — выполняет валидацию данных, возвращает объект с ошибками для невалидных полей (пустой объект, если все поля валидны)

## Слой коммуникации

### Класс LarekAPI

Отвечает за взаимодействие с сервером Web-ларька для получения данных о товарах и отправки заказов. Размещен в папке `components` (вне папки Models), так как не хранит состояние приложения. Использует **внедрение зависимостей** (Dependency Injection) через интерфейс `IApi`.

Конструктор:  
`constructor(api: IApi)` — принимает экземпляр класса, реализующего интерфейс `IApi` (например, базовый класс `Api`), для выполнения запросов.

Поля класса:  
`_api: IApi` — экземпляр класса для выполнения HTTP-запросов.

Методы класса:  
`getProductList(): Promise<IProductListResponse>` — выполняет GET запрос к эндпоинту `/product/`, возвращает объект со списком товаров.  
`orderProducts(order: IOrder): Promise<IOrderResult>` — выполняет POST запрос к эндпоинту `/order/`, передает данные заказа и возвращает результат оформления.


## Архитектура слоя View (Представление)

Слой View отвечает только за отображение данных и уведомление приложения о действиях пользователя. Компоненты View не хранят данные приложения и не принимают решений о бизнес-логике.

### Иерархия классов
1. **`Component<T>`** — базовый абстрактный класс для всех компонентов. Хранит корневой DOM-элемент и предоставляет метод `render()`.
2. **`Card<T>`** — абстрактный родитель для всех карточек товара. Выносит только общий функционал: отображение заголовка и цены.
   - `CardCatalog` — карточка товара в общем каталоге (добавляет отображение изображения и категории).
   - `CardPreview` — детальная карточка товара в модальном окне (добавляет отображение изображения, категории, описания и кнопки).
   - `CardBasket` — карточка товара внутри корзины (добавляет отображение индекса и кнопки удаления).
3. **`Form<T>`** — абстрактный родитель для всех форм. Выносит общий функционал: валидацию, отображение ошибок и блокировку кнопки отправки.
   - `OrderForm` — форма выбора способа оплаты и адреса доставки.
   - `ContactsForm` — форма ввода email и телефона.
4. **Самостоятельные компоненты** (не имеют дочерних классов):
   - `Modal` — управляет видимостью модального окна.
   - `Basket` — отображает список товаров в корзине и общую сумму.
   - `Page` — управляет счётчиком корзины и блокировкой прокрутки страницы.
   - `Success` — отображает сообщение об успешной покупке.

### Подробное описание классов представления (View)

#### Класс Component\<T\>
Базовый абстрактный класс для всех компонентов.
- **Конструктор:** `constructor(container: HTMLElement)`
- **Поля:** `container: HTMLElement`
- **Методы:** `render(data?: Partial<T>): HTMLElement`

#### Класс Card\<T\>
Абстрактный родитель для карточек. Содержит только общие элементы: заголовок и цену.
- **Конструктор:** `constructor(container: HTMLElement)`
- **Сеттеры:** `title`, `price`

#### Класс CardCatalog
Карточка товара в каталоге. Наследуется от `Card`.
- **Конструктор:** `constructor(container: HTMLElement, actions: Record<string, Function>)`
- **Сеттеры:** `image`, `category`
- **Действия:** При клике вызывает `actions.onClick`.

#### Класс CardPreview
Детальная карточка товара в модальном окне. Наследуется от `Card`.
- **Конструктор:** `constructor(container: HTMLElement, actions: Record<string, Function>)`
- **Сеттеры:** `image`, `category`, `description`, `buttonState`
- **Действия:** При клике на кнопку вызывает `actions.onClick`.

#### Класс CardBasket
Карточка товара в корзине. Наследуется от `Card`.
- **Конструктор:** `constructor(container: HTMLElement, actions: Record<string, Function>)`
- **Сеттеры:** `index`
- **Действия:** При клике на кнопку удаления вызывает `actions.onClick`.

#### Класс Form\<T\>
Абстрактный родитель для форм. Отвечает за валидацию и отображение ошибок.
- **Конструктор:** `constructor(container: HTMLFormElement, events: IEvents)`
- **Сеттеры:** `valid`, `errors`
- **Методы:** Отслеживает события `input` и `submit` внутри формы, эмитируя `form:change` и `{имя_формы}:submit`.

#### Класс OrderForm
Форма выбора способа оплаты и адреса доставки. Наследуется от `Form`.
- **Сеттеры:** `payment`, `address`
- **Действия:** При клике на кнопки оплаты эмитирует событие `form:change`.

#### Класс ContactsForm
Форма ввода email и телефона. Наследуется от `Form`.
- **Сеттеры:** `email`, `phone`

#### Класс Modal
Управляет отображением модального окна.
- **Конструктор:** `constructor(container: HTMLElement, events: IEvents)`
- **Сеттеры:** `content`
- **Методы:** `open()`, `close()` (эмитит события `modal:open` и `modal:close` для управления блокировкой страницы через класс `Page`).

#### Класс Page
Управляет глобальными элементами страницы.
- **Конструктор:** `constructor(container: HTMLElement, events: IEvents)`
- **Сеттеры:** `catalog`, `counter`, `locked`

#### Класс Basket
Отображает список товаров в корзине и итоговую сумму.
- **Конструктор:** `constructor(container: HTMLElement, events: IEvents)`
- **Сеттеры:** `items`, `total`, `selected`

#### Класс Success
Отображает экран успешного оформления заказа.
- **Конструктор:** `constructor(container: HTMLElement, events: IEvents)`
- **Сеттеры:** `total`

## События приложения

### События Моделей данных (Model)
- `catalog:changed` — изменился массив товаров в каталоге.
- `preview:changed` — изменился выбранный для просмотра товар.
- `cart:changed` — изменилось содержимое корзины.
- `order:changed` — изменились данные покупателя/заказа.

### События Представления (View)
- `card:select` — нажатие на карточку товара в каталоге (передаёт `id`).
- `card:buy` — нажатие кнопки «Купить» / «Удалить из корзины» в предпросмотре.
- `card:remove` — нажатие кнопки удаления товара внутри корзины.
- `basket:open` — нажатие на иконку корзины в шапке.
- `basket:openOrder` — нажатие кнопки «Оформить» в корзине.
- `order:submit` — нажатие кнопки «Далее» на первой форме.
- `contacts:submit` — нажатие кнопки «Оплатить» на второй форме.
- `form:change` — изменение данных в любом поле формы (передаёт `field` и `value`).
- `modal:open` — открытие модального окна (для блокировки скролла через `Page`).
- `modal:close` — закрытие модального окна (по крестику или клику вне окна).
- `success:close` — нажатие кнопки «За новыми покупками!» на экране успешного заказа.
